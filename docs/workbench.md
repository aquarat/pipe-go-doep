# Visual workbench

Updated: 2026-11-21

Run `go run ./cmd/pipe-go-doep serve -addr 0.0.0.0:8080` for LAN access, then
open the host's private address, for example <http://192.168.1.20:8080>.
Use <https://pipe-go-doep.aquarat.co.uk> for live browser synthesis. Localhost live
mode also works after `node scripts/build-web.mjs`; plain LAN HTTP uses rendered
WAV playback because browsers require a secure context for AudioWorklet.

## Four panes

1. **Output monitor**: project identity, tempo, live/recorded audio transport,
   rendered waveform, and exported-WAV peak/RMS and clipping counts. Render captures
   the current musical project independently of live playback.
2. **Score / tracker**: view ordered pattern occurrences and notes per instrument
   track, with piano-roll pitches/durations and tracker-style event detail. Rests
   occupy time; gate controls audible note duration. The visual playback cursor
   follows the selected transport. Drag the beat ruler to scrub or use its arrow,
   Home and End keys to seek.
3. **Patch / virtual rack**: module faceplates, functional icons, named jacks and
   actual cable routing. Controls display configured values/defaults. Mixer
   channels show their gains and summed routing. Drag controls vertically to edit
   values; Shift gives fine adjustment, arrow keys support keyboard editing, and
   Escape cancels an active gesture. Click a control to reveal its exact JSON
   field. Focus/zoom controls make larger patches easier to inspect. The rack
   fills the available width and grows to include every module row. Audio is
    generated by Go continuously in live mode or as a WAV when Render is pressed.
4. **Project / JSON tree**: initially closed. Branches are also initially closed.
   Expand to inspect; scalar input fields edit the project. Identity and UI
   metadata are read-only in this view. Click source links in the visualisations
   to open the matching branch. Collapse all resets tree expansion.

The source editor is a nested, initially closed section of the JSON pane.
Use it to add/remove nodes, cables or pattern rows. **Apply source** validates the
score and graph before updating the visual views. Unapplied source is saved as a
browser draft, but is not rendered or exported. Reset returns to the current
project. While source edits are pending, apply/reset them before other field edits
to avoid overwriting two competing versions of the project.

## Interactive rack editing

Known module constructor defaults are materialised in `nodes[].params` on opening
the project. Explicit values, including zero, are preserved. Thus a control always
has a concrete source field. The stereo output gain lives at `output.gain`.
Clicking a dial reveals the exact scalar field rather than just the module object.
Materialising defaults preserves DSP behaviour; exported JSON becomes more explicit.

Controls preview live audio while dragging and commit to JSON on release. Escape
restores the original parameter. Input controls
marked PATCHED edit the stored base/default value; a connected cable still supplies
their effective signal during synthesis. Static controls (for example ADSR times
and mixer channel gains) update the live module as well as the next WAV render.

## Live playback and navigation

Choose **Live synth** and press **Play**. Audio begins after a short buffer is
prepared, without rendering the whole track. Pause retains the playback position;
Stop rewinds. Choose **Rendered WAV** to navigate a fixed export instead. The
original audio controls also select rendered playback and pause the live synth.
Musical edits make the exported WAV stale, but live playback follows the project.

Drag the position slider, waveform or score ruler to scrub. With **Hear while
scrubbing** checked, live mode auditions short faded snippets at the cursor. On
release, playback resumes only if it was running before the drag. Disable the
option for silent navigation. The ruler and position slider also support keyboard
navigation. Enable **Loop** and enter a start/end in zero-based beats to repeat a
region; loop end is exclusive. Transport preferences are saved per project.

The Go engine maintains bounded state checkpoints so seeking preserves sustained
notes, oscillator phase, noise sequence and effect tails. A distant first seek can
take longer while it reconstructs the preceding state. Musical edits invalidate
old checkpoints. Compatible control changes preserve running state and smooth
continuous values; cable/score changes may briefly buffer to rebuild the patch at
the current position. Audio underruns are reported in the transport status.

The live stream uses a separate worker from WAV export. Detached panes control the
same transport; opening a different project stops and releases the old live engine.

Select an existing cable and drag an endpoint to a matching input/output jack.
Source fan-out is preserved: the selected connection is the one being reconnected.
An invalid target, occupied input, cycle or cancelled drag leaves the original
connection intact. The Go compiler also checks proposed routing before it commits.
Stereo bus cables support moving their source; their left/right destination is
the fixed output channel. Adding/removing cables remains available in JSON source.

## Separate pane windows

Use **Pop out** on Output monitor, Score, Rack or JSON. Use **Pop in** in either
window, or close the detached window, to return it. Multiple panes can be detached
at once. The actual controls move between documents: they share one project and
one browser-draft writer, so edits immediately update the other views without
competing full-project copies. JSON source edits, tree selection and audio controls
retain their existing event handlers.

Opening a different project or reloading/closing the main workbench returns the
panes. Detached windows are session-local, not automatically reopened on refresh.
Pane expansion/view preferences remain keyed by project UUID. If the browser blocks
a popup, allow popups for this preview and use Pop out again.

## What is saved where?

| State | Storage | Travels in Save JSON? |
| --- | --- | --- |
| Music, graph, title, project UUID | Project JSON | Yes |
| Expanded tree branches | `_ui.tree_expanded`, JSON Pointer strings | Yes |
| Pane visibility | Browser storage keyed by UUID | No |
| Score/rack view preferences | Browser storage keyed by UUID | No |
| Transport source, scrub audition, loop range | Browser storage keyed by UUID | No |
| Current project and pending source draft | Browser storage keyed by UUID | Only applied project |
| Rendered WAV | Browser memory until downloaded | Separate WAV download |

Every project has a top-level `id` UUID. The Go CLI still accepts older files
without one; the browser assigns a UUID on opening and includes it when saving.
UUID generation also works over plain LAN HTTP, using `crypto.getRandomValues`.
The bundled examples have stable IDs. Importing a project with the same UUID
reuses its browser view preferences; changing UUID in source creates a separate
browser identity. Browser projects lets you reopen locally saved drafts. Loading
an example reopens its local draft if one exists; importing a file explicitly
uses the imported project contents.

Tree paths use JSON Pointer escaping (`~0` for `~`, `~1` for `/`). The root is `""`.
An empty list means every branch is collapsed. Closing a parent keeps remembered
child expansions, so reopening it restores that view. Array paths are positional:
inserting/reordering elements can make a remembered expansion refer to a different
element. Use Collapse all if reorganising the project substantially.

Keeping tree paths in one `_ui` section avoids adding editor properties to note
steps, arrays or DSP parameter maps. Metadata does not change audio or invalidate
an existing render. The backend rejects malformed or excessive metadata.

Browser keys are prefixed `pipe-go-doep.project.v2.<UUID>`; the last project key is
`pipe-go-doep.last-project.v2`. The original single-draft format is migrated when
there is no newer saved project. Browser storage is scoped to scheme/host/port:
opening localhost and the LAN IP uses separate workspaces. Export JSON to move a
project between browsers; use normal browser site-data controls to clear drafts.

## Development checks

Pure model/state tests need only Node.js:

```sh
node --test internal/workbench/static/*.test.mjs
```

An optional end-to-end check uses an external Playwright installation and a running
preview. It creates an isolated browser context, so it does not change your drafts:

```sh
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
CHROMIUM_PATH=/path/to/chrome \
WORKBENCH_URL=http://127.0.0.1:8080 \
node --test internal/workbench/workbench.browser.mjs
# Also check live PCM output, navigation, loops and popup controls:
node --test internal/workbench/live.browser.mjs
```

It checks project isolation, immediate-reload pane persistence, JSON tree export,
audio render/playback, stale-audio seek blocking, pending-source recovery, delayed
project-load races, expansion limits and mobile overflow. See the score/rack
visualisation references for component-level checks.

## Oscilloscope

The first rack faceplate is a probe oscilloscope with X and Y1–Y4 jacks. Drag
from a scope jack to any module jack (input or output) or to the stereo output
jacks; drag a selected probe cable's plug to move it, and drop it on empty space,
press Delete or use **Unplug** to remove it. Probes are stored in `_ui.scope`, so
they travel with the project JSON without affecting sound or WAV export.

The scope draws while **Live synth** plays and freezes when paused. **YT** plots
the Y inputs against time (time base, per-channel scale/offset, trigger source,
level, slope and auto/normal/free-run); **XY** plots each Y input against X with
adjustable persistence. **Auto** fits scales and the trigger level to the
current signals. Display settings are saved in this browser per project. See
[oscilloscope](scope.md).
